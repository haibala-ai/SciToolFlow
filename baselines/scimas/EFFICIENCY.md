# SciMas 实现效率

本轮优化针对请求组织、本地重复计算和轨迹写入。Planner、Executor、Reviewer 的职责、逐结果科学审查、门控、局部修复和最终提交规则保持不变，题目和评分器也未调整。

## 上下文与缓存

每次角色请求仍是独立上下文，包含三段消息：角色指令、当前任务与图等稳定内容、响应结构与当前执行状态。稳定内容放在前面，变化的就绪节点、观测接受状态、经验及纠错反馈放在后面；初始 Planner 也将任务与响应结构放在变化的规划指令之前。

这种布局为服务端提供更长的相同前缀。它没有跨角色共享会话，没有缓存模型回答，也没有用摘要替代原始证据。实际能否命中 KV／prompt cache 取决于所用服务、缓存容量、请求路由和结构化输出实现；字符前缀相同不能等同于实际命中。

请求 JSON 使用紧凑编码，保留所有字段和值。原有预览长度、截断标记和完整证据查询入口保持一致；超过上下文上限时仍明确失败，不静默丢弃科学依据。各角色的 prompt 在本任务内只读取一次，任务之间没有答案记忆。

## 本地执行开销

- 工具图谱连接候选使用实例内、最多 64 组的缓存。它只复用契约兼容性计算；每个检索查询仍按自己的相关度重新排序，返回独立副本。重新加载图谱会创建新缓存。
- 原始输出写入后不再变化，因此缓存其有界预览；较大的完整序列化文本不会长期保留在缓存中。观测是否陈旧、是否被当前图接受仍逐次检查，不能因缓存保留失效证据。
- 构建一次上下文时，每个已有观测涉及的节点身份只计算一次，供该轮观测检查共用。
- 轨迹采用紧凑 JSON，继续保留全部原始请求、响应和调用。原子替换、落盘同步以及执行边界的检查点都保留。编辑器可格式化查看。
- 逐步时间、解析决策、派发参数和诊断字段复用原有检查点；单请求文件与 Markdown 案例报告按需离线导出，运行中不生成这些副本。新增字段有少量编码成本，真实墙钟计时保留全部运行内日志开销。

另修复了通用角色循环覆盖调用者反馈的问题：答案格式纠错和 Reviewer 的科学修正意见现在会与后续检查／思考记录一起传递。这避免模型因未收到已有反馈而徒劳重试。

新版 Mini 抽测还发现条件计算的协议歧义：报告必须包含某个字段，不等于该字段对应的科学计算必须无条件执行。Planner 说明现明确区分无条件判定证据与允许筛选的后续计算，保留被筛选对象所要求的空值或原因报告；不会为了减少工作而把无条件要求改为筛选。验证器规则未改变。

## 同信息离线对比

固定此前两条真实轨迹的角色指令与证据，对 **54 次请求**的上下文序列化做逐请求对比，断言重新组织前后的 JSON 信息完全一致。此测量隔离序列化收益，不包括后续规划说明澄清带来的指令长度变化。采用本地 Qwen3.5 tokenizer 对消息正文计数，**不是 Terra 的实际用量，也不包含聊天模板开销**。

| 观测项 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 输入正文 token 数 | 404,601 | 351,346（减少 13.2%） |
| 同角色相邻请求的共同前缀字符总数 | 712,880 | 764,047 |
| 示例轨迹文件大小 | 1,876,705 B | 1,585,927 B |
| 6 组图谱连接查询中位耗时 | 4.07 ms（冷缓存） | 1.94 ms（热缓存） |
| 示例轨迹检查点写入中位耗时 | 28.69 ms | 23.56 ms |

计入当前 Planner 说明澄清带来的额外 945 个正文 token 后，同一固定请求集合的代理总数为 352,291，较优化前减少约 **12.9%**。这仍是离线固定输入测量，实际运行的决策数量和输出长度会随模型行为变化。

前缀字符总数只用于定位布局问题，不是缓存命中 token 数。查询、写入耗时是本机局部微测量，不能外推为完整任务加速比。实际服务的输出 token、缓存用量和延迟应以同题同模型实验及后端返回的 `usage` 为准。

可复现离线测量：

```bash
python -m tests.scimas.profile_efficiency \
  --trajectories /path/to/before/trajectory.json \
  --tokenizer /path/to/tokenizer.json \
  --output results/scimas_profile.json
```

该脚本用于旧版双消息请求，比较相同证据的序列化方式；不生成答案、不调用评分参考。结果中的 `content_tokens` 是指定 tokenizer 的正文计数。生产轨迹的 `context_usage` 记录本轮输入字符数和与同角色上次请求的共同前缀字符数；真实后端 token 用量仍保留在原有资源账本中，未返回时保持未知。

## 效果检查

专项回归覆盖上下文信息等价、契约缓存重排和隔离、纠错反馈传递，以及原有图修复、过期证据、并行取消、科学门控和轨迹认证边界。新版 Mini 的 `SMAS-0041`（协方差门控）和 `SMAS-0045`（并行资源分配）使用独立、信息受限的 GPT-6.1 Terra 子智能体运行真实工具，再按统一入口评分。

抽测仅报告运行完成率、工具规划准确率和答案准确率。它用于检查实现回归，不是 Mini-200 的整体成绩；子智能体调度时间也不作为生产推理延迟。实际结果与诊断见 `results/reports/scimas_efficiency_20261105/`。


### 新版 Mini 最终抽测

| 任务 | 运行完成率 | 工具规划准确率 | 答案准确率 | 模型请求／科学调用 |
| --- | ---: | ---: | ---: | ---: |
| SMAS-0041：协方差筛选与条件求解 | 100% | 100% | 100% | 18／8 |
| SMAS-0045：多场景资源分配 | 100% | 100% | 100% | 21／10 |

两题的轨迹和资源身份核验通过，均无待人工复核项、协议错误或答案格式错误。另由公开输入的二阶矩阵解析公式、线性规划可行顶点枚举独立核对全部答案字段，结果一致。全部 39 份请求与实际消费的回复一一匹配，每个运行的 215 个 actor 文件身份一致。

对这 39 次实际请求固定其信息和角色指令，仅将上下文组织还原为原来的方式进行离线对照，正文 token 代理计数为 **350,966 → 300,768，减少 14.3%**。同样使用本地 Qwen tokenizer，不表示 Terra 的实际 token 用量或缓存命中率。没有运行一个对应的随机化旧版对照实验，因此不将该测量解释为端到端的总成本或延迟降幅。

最终代码通过 **87 项 SciMas 测试、1,181 项全项目测试与 801 项子测试**。本轮早期的传输身份错误、embedding SSL 故障、条件需求解释错误和断线中断均保留原记录；它们不被覆盖为成功。抽测用于开发验收，不是两题一次尝试成功率或 Mini-200 整体性能。

详细记录：`results/reports/scimas_efficiency_20261105/acceptance.json`；真实运行位于 `results/scimas_efficiency_20261105_covariance_final/` 与 `results/scimas_efficiency_20261105_allocation_final/`。
